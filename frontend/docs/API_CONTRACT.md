# Контракт фронтенда и бэкенда — v1

Фронтенд использует реализованный контракт **`/api/v1`**. Полное описание и схемы находятся
в [docs/API.md](../../docs/API.md) и [docs/openapi.json](../../docs/openapi.json).
Предыдущее предложение одиночного `POST /documents` больше не используется.

## Адреса и доступ

По умолчанию `VITE_API_BASE_URL=/api/v1`. В production сайт и API обслуживает FastAPI
по адресу `http://127.0.0.1:8000`; Vite в разработке проксирует `/api` и `/health` на порт 8000.
`GET /health` находится в корне сервера и возвращает `mode`, `analysis_ready`, `status`, `version`.
Режим `demo` означает правила без ИИ; `llm` — обращения к настроенному провайдеру модели.

Если задан `API_TOKEN`, все запросы `/api/v1` включают `Authorization: Bearer <токен приложения>`.
Модельный ключ браузер не получает. `/health`, `/docs`, `/openapi.json` и файлы интерфейса
доступны без этого токена. `VITE_*` не должны содержать секретов.
Токен вводится пользователем в разделе «Доступ к серверу» и хранится в sessionStorage
текущей вкладки под ключом `larpsec.apiToken`; после «Сохранить подключение» клиент
прикладывает его к запросам API. Это общий токен команды, не ключ провайдера модели.

## Последовательность

| Действие | Запрос относительно `/api/v1` | Результат |
| --- | --- | --- |
| Список сравнений | `GET /comparisons?limit=20&offset=0` | Массив `Comparison` |
| Создать сравнение | `POST /comparisons` | HTTP 201, `Comparison` с `id` |
| Добавить файл | `POST /comparisons/{id}/documents?side=before` или `after` | HTTP 201, `Document` |
| Читать текст | `GET /comparisons/{id}/documents/{document_id}/fragments` | Массив `Fragment`, пагинация |
| Удалить файл | `DELETE /comparisons/{id}/documents/{document_id}` | HTTP 204 |
| Подтвердить комплект | `PATCH /comparisons/{id}/coverage` | `Comparison` |
| Запустить анализ | `POST /comparisons/{id}/analyze` | HTTP 202, `Comparison` |
| Проверить состояние | `GET /comparisons/{id}` | `Comparison` |
| Получить результат | `GET /comparisons/{id}/result` | `Result` |
| Открыть цитату | `GET /comparisons/{id}/sources/{fragment_id}` | `Fragment` |
| Скачать оригинал | `GET /comparisons/{id}/documents/{document_id}/download` | Исходный файл |
| Оценить замечание | `PATCH /comparisons/{id}/findings/{finding_id}/review` | `ReviewRecord` |
| Скачать заключение | `GET /comparisons/{id}/report?format=markdown` или `json` | Файл |

При создании передаются `title`, `before_complete`, `after_complete`; все необязательны,
полнота по умолчанию `false`. PATCH полноты требует оба флага.

Загрузка: multipart-поле **`file`**, параметр стороны **`side` находится в query**.
Один запрос содержит один DOCX/PDF/XLSX. Заголовок Content-Type с boundary выставляет
браузер. Сервер синхронно извлекает и сохраняет фрагменты при загрузке; отдельного
асинхронного состояния документа `ready/processing` в контракте нет.
Фрагменты читаются страницами: `limit=200`, максимум 1000, `offset=0`.

## Выполнение и восстановление

Статусы сравнения: `draft`, `queued`, `running`, `completed`, `failed`.
Для отображения используются серверные `stage`, `progress`, `error`.
Во время анализа клиент опрашивает сравнение; при `completed` загружает `/result`.
Отмена ожидания в браузере не отменяет серверное задание. После обновления страницы
состояние и результат читаются из того же сравнения.

Повторный `/analyze` для `queued/running/completed` не создаёт новый запуск.
Для `failed` он явно повторяет анализ. Добавление и удаление файлов, изменение полноты
разрешены только в `draft/failed`. Результат до завершения возвращает HTTP 409.
При перезапуске сервера прерванное задание получает `failed` с кодом `interrupted`.

## Результат и источники

`Result` содержит `units`, `functions`, `reporting`, `unit_changes`, `function_changes`,
`findings`, `warnings`, `coverage`, `summary`, `reviews`, а также режим и модель.
Тип функции `duty/permission/prohibition` нужно сохранять при отображении: запрет
и обязанность выполнять одинаковое действие имеют разный смысл.

Каждое доказательство содержит `fragment_id` и `quote`. Идентификатор используется
целиком в `/sources/{fragment_id}`. Ответ содержит `document_id`, `text`, `locator`,
`clause`, `page`, `sheet`, `cell_range`. Название файла берётся из `comparison.documents`.
DOCX адресуется пунктом/абзацем, PDF страницей, XLSX листом и ячейками.
Цитаты отображаются как текст; не используйте `innerHTML`.

`potential_loss`, `duplication`, `conflict`, `coverage_gap` — замечания для проверки.
Неполное покрытие не позволяет утверждать потерю функции. Проверка сотрудником имеет
статус `unreviewed/confirmed/dismissed` и необязательный комментарий до 2000 символов.
Оценки возвращаются отдельно в `reviews`; без записи замечание считается `unreviewed`.

## Ошибки

HTTP-ошибка имеет вид `{"error":{"code":"...","message":"..."}}`.
Ошибка фонового задания находится в `comparison.error` при `status=failed`.
Не подменяйте ошибки локальными, учебными или ранее полученными результатами.

401 — нужен токен; 404 — ресурс не найден; 409 — заблокированный комплект, дубликат
или ещё не готовый результат; 413 — лимит размера/количества; 415 — формат;
422 — параметры или повреждённый документ; 429 — очередь заполнена;
503 — модель не настроена или сервер завершает работу. Сообщения выводятся обычным текстом.

## Проверка интеграции

Запустить `./run.sh`, открыть сайт на 8000 и загрузить учебную пару `before.docx/after.docx`.
Проверить сохранение черновика, запуск и завершение, исходные цитаты, отчёт и повторное
открытие результата после обновления страницы. Dev-режим на 5173 должен выполнять тот же
сценарий через прокси. Ошибочный `/api/v1/...` возвращает HTTP 404, а не HTML сайта.
