# Larpsec — анализ организационной структуры и функций

Веб-приложение для HackAlem. Принимает комплекты документов **до/после реорганизации**,
извлекает подразделения и функции, сопоставляет их и формирует замечания с проверяемыми
цитатами: потенциальные потери, дублирование и конфликты полномочий.

Интерфейс: React, TypeScript, Vite. Сервер: Python 3.12–3.14, FastAPI, Pydantic,
SQLite, python-docx, pypdf, openpyxl, httpx. Зависимости зафиксированы в
`frontend/pnpm-lock.yaml` и `backend/uv.lock`.

## Быстрый запуск

Нужны Node.js **22.12+** с npm/npx, Python **3.12–3.14** и
[uv](https://docs.astral.sh/uv/getting-started/installation/).
На Linux/macOS из корня репозитория:

```bash
./run.sh
```

Скрипт устанавливает зависимости по lock-файлам, собирает фронтенд и запускает сервер.
Откройте **http://127.0.0.1:8000**: сайт и API работают по одному адресу.
pnpm берётся через npx в версии из `frontend/package.json`; глобальная установка не нужна.
При первом запуске нужен доступ к реестрам зависимостей.

По умолчанию работает демонстрационный анализ **без ИИ, ключей и обращений к модели**.
Сервер обрабатывает загруженные документы буквальными правилами; это не заранее
подставленный результат. Свободные формулировки требуют настройки режима `llm` ниже.
Порт можно изменить: `PORT=8001 ./run.sh`.

- Swagger UI: http://127.0.0.1:8000/docs
- Фронтенд и разработка интерфейса: [frontend/README.md](frontend/README.md)
- Проверка сервера: http://127.0.0.1:8000/health
- Контракт для фронтенда: [docs/API.md](docs/API.md)
- Машиночитаемая схема: [docs/openapi.json](docs/openapi.json)
- Архитектура и ограничения: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- Пример результата: [docs/example-result.json](docs/example-result.json)
- Результаты проверки: [docs/VALIDATION.md](docs/VALIDATION.md)

Каталог `backend/data/` содержит БД, оригиналы и учебные файлы; он исключён из Git.
Скрипт не изменяет `.env`. Без него применяются локальные значения по умолчанию.
Для остановки нажмите Ctrl+C. База и загруженные документы сохраняются между запусками.

## Демонстрация полного сценария

На сайте нажмите **«Загрузить пример „до/после“»**, затем **«Запустить сравнение»**.
Учебная пара DOCX действительно загружается на сервер и анализируется в текущем режиме.
После завершения нажмите **«Открыть результаты»**: доступны сопоставления, замечания,
исходные цитаты и выгрузка отчёта. После обновления страницы результат остаётся в базе.

Для своих документов используйте **«Выбрать документ»**, сторону «до»/«после» и
**«Обработать документ»**. Перед сравнением проверьте состав и полноту обоих комплектов.

Для проверки того же сценария через командную строку:

При работающем сервере во втором терминале:

```bash
cd backend
uv run --frozen --no-dev python -m scripts.demo_client
```

Команда создаёт учебные документы, загружает их через API, дожидается завершения анализа
и сохраняет `data/demo/result.json` и `data/demo/report.md`. Она каждый раз создаёт новое
сравнение. При настроенном llm выполняются реальные запросы к модели.

Искусственный пример по мотивам положения о внутреннем аудите содержит:

- переименование департамента непрерывного мониторинга;
- перенос подготовки отчёта в другой департамент;
- исчезновение функции проверки сохранности активов;
- дублирование проверки прав доступа;
- обязанность утверждать платежи, противоречащую запрету;
- новый отдел аналитики;
- контрольные случаи без нарушений: двойное подчинение и функции в разных областях.

Описание и ожидаемые изменения: [examples/scenario.json](examples/scenario.json).
Учебные документы явно обозначены как синтетические. Документы организатора из `~/Hackalem`
в репозиторий не копируются.

На сайте создайте сравнение, загрузите документы в группы «до» и «после», укажите полноту
комплектов и запустите анализ. Результат содержит сопоставление структуры и функций,
замечания, ссылки на исходные фрагменты и выгрузку заключения. Для ручной демонстрации
можно загрузить `backend/data/demo/before.docx` и `backend/data/demo/after.docx`,
созданные приведённой командой.

Только генерация DOCX/XLSX без запуска анализа:

```bash
cd backend
uv run --frozen --no-dev python -m scripts.make_demo
```

## Настоящий ИИ-анализ

```bash
cp backend/.env.example backend/.env
```

Заполните локальный `backend/.env`:

```dotenv
ANALYSIS_MODE=llm
LLM_API_KEY=ваш_ключ_в_локальном_файле
LLM_MODEL=имя_доступной_вам_модели
LLM_BASE_URL=https://api.openai.com/v1
```

Перезапустите сервер. Модель должна поддерживать **Responses API со strict JSON Schema**.
Универсальная совместимость с любым OpenAI-compatible Chat Completions endpoint не заявляется.
Ключ не передаётся фронтенду и не попадает в Git. В этом режиме текст документов передаётся
настроенному провайдеру; возможны расходы на API. Без ключа `/analyze` вернёт понятную ошибку.

`demo` использует ограниченные буквальные правила и всегда обозначается в результате
как режим без ИИ. При ошибке настоящей модели сервер не заменяет результат демонстрационным.
Живая модель требует отдельной проверки на контрольном комплекте после настройки ключа.

## Пример запросов

Создать сравнение:

```bash
curl -s http://127.0.0.1:8000/api/v1/comparisons \
  -H 'Content-Type: application/json' \
  -d '{"title":"Сравнение положений","before_complete":true,"after_complete":true}'
```

Возьмите `id` из ответа и подставьте его вместо `COMPARISON_ID`:

```bash
curl -s -F 'file=@backend/data/demo/before.docx' \
  'http://127.0.0.1:8000/api/v1/comparisons/COMPARISON_ID/documents?side=before'
curl -s -F 'file=@backend/data/demo/after.docx' \
  'http://127.0.0.1:8000/api/v1/comparisons/COMPARISON_ID/documents?side=after'
curl -s -X POST http://127.0.0.1:8000/api/v1/comparisons/COMPARISON_ID/analyze
curl -s http://127.0.0.1:8000/api/v1/comparisons/COMPARISON_ID
curl -s http://127.0.0.1:8000/api/v1/comparisons/COMPARISON_ID/result
```

Последний запрос выполняется после статуса `completed`. При настроенном `API_TOKEN`
добавляйте `-H 'Authorization: Bearer ВАШ_ТОКЕН_ПРИЛОЖЕНИЯ'`.
Для `scripts.demo_client` передайте тот же токен через переменную окружения `API_TOKEN`.
На сайте раскройте **«Доступ к серверу»**, заполните **«Токен доступа»** и нажмите
**«Сохранить подключение»**. Токен хранится в sessionStorage текущей вкладки, не в сборке.

## Проверки и разработка

Для работы только с сервером: `./backend/run.sh`. Если `frontend/dist` уже существует,
он также доступен на корневом URL; после изменения фронтенда нужна новая сборка.
Для разработки интерфейса с обновлением страницы на лету используйте отдельный Vite
на порту 5173, как описано в [frontend/README.md](frontend/README.md).

```bash
cd backend
uv sync --frozen --group dev
uv run --frozen pytest -q
uv run --frozen ruff check app tests scripts
uv run --frozen python -m scripts.export_openapi
```

Проверяются полный HTTP-сценарий, источники, перенос/потеря/дублирование/конфликт,
отсутствие ложных срабатываний на контрольных примерах, четыре формата документов,
ошибки и ограничения загрузки, сохранность результатов после перезапуска,
параллельные запросы, токен доступа и модельный адаптер с тестовым HTTP-провайдером.
Тесты не используют реальный ключ и не выполняют платных вызовов модели.

Для команды: серверный код — в `backend/`; фронтенд может работать независимо через
версионированный контракт `/api/v1`. Изменения контракта нужно отражать в `docs/API.md`
и заново экспортировать OpenAPI. Изменения другого разработчика следует получать и
согласовывать перед объединением веток.

## Docker

Альтернативный запуск при установленном Docker Compose:

```bash
docker compose up --build
```

Нужен Docker Compose с поддержкой необязательного `env_file` (`required: false`).
Фронтенд собирается внутри Docker; Node.js, Python и uv на хосте не нужны.
Сайт открывается на **http://127.0.0.1:8000**. Если `backend/.env` существует, настройки
режима и токена читаются из него; без файла работает demo.
SQLite и оригиналы сохраняются в именованном томе `analysis_data`.
Сервис привязан к localhost. Docker-сборка требует отдельной проверки в среде с Docker.

## Практические ограничения

Прототип обслуживает одну доверенную команду и работает одним процессом (`--workers 1`).
Общий `API_TOKEN` можно задать для доступа команды; пользовательских аккаунтов и изоляции
между ними пока нет. На Windows используйте Docker или WSL.

Поддерживаются DOCX, PDF с текстовым слоем, Excel (.xlsx) и TXT. OCR, бинарные DOC/XLS, интерпретация
графических оргструктур и вычисление Excel-формул не реализованы; ограничения извлечения
показываются пользователю. По умолчанию допускается 20 файлов по 20 МБ и 400 функций
в одном сравнении. Настройки и остальные ограничения описаны в `.env.example` и архитектуре.

Подтверждение полноты документов не гарантирует полноту извлечения моделью. Цитаты
проверяются на существование, а смысл выводов требует проверки сотрудником.
Проверка внешнего законодательства и сравнение с другими операторами остаются
опциональными направлениями развития.
